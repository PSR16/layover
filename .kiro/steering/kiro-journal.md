# Build journal rules (Kiroween 2026)

Judges score how well Kiro was used. Keep #[[file:docs/kiro-log.md]] accurate as we work.

## When to log
Before saying any of these is done, add or update an entry in docs/kiro-log.md:
- a spec task, or a change to requirements, design or tasks
- creating or changing a hook, steering file, custom agent, MCP server or power
- a test failing, especially a property-based test (record the counterexample)
- a hook or agent catching a problem
- me correcting, rejecting or overriding your work
- a commit (record the hash)

## How to log
- Add a Timeline entry using the format in the file, then update the matching numbered section and its table.
- Be specific: file names, requirement IDs (R?), evidence IDs (E?), test names, commit hashes.
- Quote my corrections briefly, in my words.
- Record what actually happened. Don't exaggerate. Don't log features we didn't use.
- If something went wrong, log it under Mistakes and fixes. Honest mistakes are useful evidence.
- Add good demo moments to "Screenshots to take."
- Never delete entries. Add "Update:" lines.
- Never write in lines starting with "Me:". Those are mine. If a "Me:" line is empty after a notable moment, remind me to fill it in.

## Keep it short
Each Timeline entry should be 3–8 lines. Put detail in the tables.
